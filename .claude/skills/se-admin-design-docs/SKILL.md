# SE管理画面 設計資料スキル

`documents/SE管理画面/` 配下に、SE管理画面開発プロジェクトの要件定義・設計・テスト資料一式（Markdown、計20ファイル）が格納されている。SE管理画面に関するコード（実装・修正・レビュー・テスト作成）に着手する前に、該当する資料を読んで仕様・制約を確認すること。

## いつ使うか

以下のような作業のときにこのスキルを参照する。
- SE管理画面（管理者ログイン、ダッシュボード、顧客アカウント発行、SE管理者アカウント管理、CLIツール等）に関する実装・修正
- 上記機能のAPI・DB・画面仕様についての質問への回答
- 上記機能に関するテスト設計・テストコード作成
- 上記機能のコードレビュー（仕様との整合性確認）

## プロジェクト概要（要点）

一般ユーザー向けのマイページ/ログインとは**完全に分離**された、システム管理者（SE）専用の管理画面を新規構築する案件。

- インスコープ: 管理者認証（ID/PWログイン）、ダッシュボード、顧客アカウント新規発行画面、SE管理者アカウント追加/削除用CLIツール
- アウトスコープ: 一般ユーザー向け機能、インフラ設計・構築
- 技術スタック: フロントエンド React（Tailwind CSS / MUI / Headless UI, S3+CloudFront配信）、バックエンド TypeScript / Hono（セッションベース認証, REST API）、DB PostgreSQL（全システム共通DB）、メール AWS SES、監視 Sentry、インフラ AWS
- セキュリティ要件: パスワードは bcrypt でソルト付きハッシュ化、連続ログイン失敗5回でアカウントロック、無操作30分でセッションタイムアウト、通信はTLS1.2以上、監査ログは1年保持

詳細・確定していない仕様には資料中に `※要確認` の注記がある。実装時にこの注記がある項目は、資料だけで断定せず、必要に応じてユーザーに確認すること。

## 使い方の指針

1. 作業対象の機能（例: ログイン、顧客アカウント発行）に該当する要件定義・設計ファイルをまず読み、仕様・制約を把握する。
2. テストケースを書く/レビューする場合は、テスト計画（マップ）で該当機能グループの観点を確認してから、観点ファイル→詳細テストファイルの順に読む。
3. `※要確認` の記載がある箇所を実装の前提にする場合は、ユーザーに確認してから進める。
4. 各ファイルは外部の設計書作成支援ツールからのエクスポート形式で、`> バージョン: N | 更新日時: ...` のヘッダーを持つ。資料が更新された場合はバージョン表記で最新性を確認する。
