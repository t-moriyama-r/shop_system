## [BP-001] ログイン認証・セッション管理

- **カテゴリ:** 認証・認可
**relatedScreens:**

- SCR-001: ログイン画面
- SCR-003: ダッシュボード画面

- **説明:** SE管理者がメールアドレスとパスワードを使ってシステムにログインし、セッションを開始・維持・破棄する機能。パスワード未設定ユーザーの初回ログイン誘導、連続ログイン失敗時のアカウントロックも含む。
**relatedTables:**

- se_admin_users
- sessions
- audit_logs

**security:**

- auth: ログイン操作自体は未認証状態で実行可能。ログアウトおよびセッション検証はセッション認証が必要。
- permissions: なし（公開エンドポイント：ログイン）,セッション認証済み（ログアウト・セッション検証）

**operations:**

- **ログイン**
  - type: CREATE
  - トリガー: ログイン画面にてメールアドレス・パスワードを入力し、ログインボタンを押下
- **セッション検証**
  - type: READ
  - トリガー: 認証が必要なAPIエンドポイントへのリクエスト時（ミドルウェアとして毎回実行）
- **ログアウト**
  - type: DELETE
  - トリガー: 管理画面共通ヘッダーのログアウトボタンを押下

- **備考:** パスワードはbcryptでハッシュ化して保存。セッションIDはHttpOnly・Secure・SameSite=Strict属性のCookieで管理する。セッションタイムアウト時間（30分）は※要確認。

## [BP-002] SE管理者アカウント管理

- **カテゴリ:** マスタ管理
**relatedScreens:**

- SCR-002: 初回パスワード設定画面
- SCR-006: SE管理者アカウント管理画面

- **説明:** SE管理者アカウントのパスワード設定（初回ログイン時の必須操作）、一覧取得、および論理削除を行う機能。新規アカウント追加はDBへの直接書き込みで行うため、本機能ではパスワード設定・一覧取得・削除のみを扱う。
**relatedTables:**

- se_admin_users
- sessions
- audit_logs

**security:**

- auth: セッション認証必須
- permissions: SE管理者ロール ※要確認（削除操作に上位権限が必要か）

**operations:**

- **パスワード設定**
  - type: UPDATE
  - トリガー: 初回パスワード設定画面にてパスワードを入力し、設定ボタンを押下
- **SE管理者アカウント一覧取得**
  - type: READ
  - トリガー: SE管理者アカウント管理画面の初期表示時、検索・ソート・ページ切り替え操作時
- **SE管理者アカウント削除**
  - type: DELETE
  - トリガー: SE管理者アカウント管理画面にて対象行の削除ボタンを押下し、削除確認ダイアログで削除実行ボタンを押下
- **アカウントロック解除**
  - type: UPDATE
  - トリガー: SE管理者アカウント管理画面にてロック解除ボタンを押下 ※要確認（ロック解除操作の画面・UIの有無）

- **備考:** SE管理者アカウントの新規追加はDBへの直接書き込み（CLIツール等）で行うため、本バックエンド処理には含まない。パスワードポリシーの詳細（文字種要件等）は※要確認。

**relatedScreens:**

**relatedTables:**

- shop_accounts
- se_admin_users
- audit_logs
- email_notification_logs

**security:**

- auth: セッション認証必須
- permissions: SE管理者ロール

**operations:**

- **顧客アカウント新規発行（登録）**
  - type: CREATE
  - トリガー: 顧客アカウント新規発行画面にて必要情報を入力し、発行ボタンを押下
- **顧客アカウント一覧取得**
  - type: READ
  - トリガー: ダッシュボード画面表示時、または顧客アカウント一覧画面への遷移時 ※要確認（一覧専用画面の有無）
- **顧客アカウント詳細取得**
  - type: READ
  - トリガー: 一覧から特定の顧客アカウントを選択した時、または発行完了画面での情報表示時
- **顧客アカウント削除**
  - type: DELETE
  - トリガー: 顧客アカウント詳細画面または一覧画面にて削除ボタンを押下 ※要確認（削除機能の要否・画面の有無）

- **備考:** 顧客アカウント発行後のメール通知はBP-005（メール通知送信処理）が担当する。initial_password_hashはAPIレスポンスに含めず、メール本文でのみ平文の一時パスワードを通知する。

## [BP-005] メール通知送信処理

- **カテゴリ:** 外部連携
**relatedScreens:**

- SCR-004: 顧客アカウント新規発行画面（間接的に連携）
- SCR-005: 顧客アカウント発行完了画面（ステータス参照）

- **説明:** 顧客アカウント発行完了時にショップへ初期ログイン情報（メールアドレス・一時パスワード・利用案内）を自動送信するメール通知機能。送信ログの管理とリトライ処理を含む。
**relatedTables:**

- email_notification_logs
- shop_accounts

**security:**

- auth: 内部処理（バックグラウンドジョブ・キュー）のため外部認証不要
- permissions: システム内部処理

**operations:**

- **アカウント発行完了メール送信**
  - type: CREATE
  - トリガー: 顧客アカウント登録処理（BP-003）の成功後、email_notification_logsにPENDINGレコードが作成されたことをトリガーとして非同期実行
- **メール送信ステータス取得**
  - type: READ
  - トリガー: 顧客アカウント発行完了画面の表示時、またはポーリングによる定期取得
- **メール送信失敗レコード再送バッチ処理**
  - type: BATCH
  - トリガー: 定期バッチ実行（cronジョブ等） ※要確認（実行間隔・タイミング）

- **備考:** メール送信は非同期処理（キューイング）で実装することを推奨。利用するメール送信サービス（AWS SES、SendGrid等）は※要確認。メールテンプレートの内容・形式も※要確認。

## [BP-006] 監査ログ管理

- **カテゴリ:** 集計・レポート
**relatedScreens:**

- ※監査ログ閲覧専用画面は二次開発にて実装予定

- **説明:** システム内で発生した操作（ログイン成功・失敗、アカウント操作等）の監査ログを記録・参照する機能。セキュリティ監査および障害調査のための証跡管理を目的とする。ログ保持期間は1ヶ月とし、期限超過レコードの自動削除バッチを日次実行する。
**relatedTables:**

- audit_logs

**security:**

- auth: セッション認証必須（記録処理は内部呼び出し）
- permissions: SE管理者ロール ※要確認（閲覧権限の範囲）

**operations:**

- **監査ログ記録**
  - type: CREATE
  - トリガー: 各業務処理（BP-001〜BP-005）内で操作発生時に内部呼び出し
- **期限超過監査ログ自動削除バッチ**
  - type: BATCH
  - トリガー: 日次cronジョブによる定期実行（例：毎日深夜0時）

- **備考:** 監査ログはUPDATE・DELETE不可（業務処理からの改ざん防止）とする。ただし保持期間（1ヶ月）を超過したレコードのみ、日次バッチによる物理削除を行う。監査ログ閲覧専用画面は二次開発にて実装予定のため、本フェーズでは閲覧APIは含まない。

## [BP-012] 監査ログ管理

- **カテゴリ:** 集計・レポート
**relatedScreens:**

- SCR-008: エラー画面（共通）（エラー参照IDのログ記録先）
- ※監査ログ閲覧専用画面は二次開発

- **説明:** システム内で発生した操作（ログイン成功・失敗、アカウント操作等）の監査ログを記録・参照・自動削除する機能。セキュリティ監査および障害調査のための証跡管理を目的とする。ログ保持期間は1ヶ月とし、日次バッチで自動削除する。閲覧専用画面は二次開発で実装予定。
**relatedTables:**

- audit_logs

**security:**

- auth: 記録処理は内部呼び出しのため認証不要。参照処理はセッション認証必須（二次開発時に実装）。
- permissions: システム内部処理（記録）,SE管理者ロール（参照・二次開発）

**operations:**

- **監査ログ記録**
  - type: CREATE
  - トリガー: 各業務処理（BP-001〜BP-005）内で操作発生時に内部呼び出し
- **期限切れ監査ログ自動削除（日次バッチ）**
  - type: BATCH
  - トリガー: 日次cronジョブによる定期実行（例：毎日午前2時）

- **備考:** 監査ログはaudit_logsテーブルへのINSERTのみを許可し、UPDATE・DELETEを不可とすることで改ざん防止を実現する。アプリケーション層では記録処理（INSERT）と期限切れ削除処理（DELETE）以外の書き込み手段を提供しないことに加え、DBトリガー（`audit_logs_prevent_tamper`）でもUPDATEを常に拒否し、DELETEはクリーンアップバッチが明示的に許可設定（`app.audit_log_delete_allowed`）を有効化した場合のみ許可する（詳細は `documents/運用/監査ログクリーンアップ.md` を参照）。ログの保持期間は1ヶ月とし、日次バッチで自動削除する。監査ログ閲覧専用画面は二次開発で実装予定のため、一次開発では記録・自動削除機能のみを実装する。
