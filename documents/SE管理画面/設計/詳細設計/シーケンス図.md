## ユーザー認証

SE管理者がメールアドレスとパスワードでログインし、セッションを開始する処理。パスワード未設定時の初回設定誘導、ログイン失敗によるアカウントロックを含む。

**参加者:** SE管理者 (actor)、フロントエンド (system)、APIサーバー (system)、データベース (database)

**メッセージフロー:**
- SE管理者 → フロントエンド: メールアドレス・パスワード入力 → ログインボタン押下
- フロントエンド → APIサーバー: POST /api/auth/login
{email, password}
- APIサーバー → APIサーバー: 入力バリデーション
（email形式・password必須チェック）
- APIサーバー → データベース: SE管理者情報取得
（email検索）
  - データベース ← APIサーバー: SE管理者レコード
（is_deleted, is_locked, is_password_set, password_hash）
- APIサーバー → APIサーバー: アカウント状態チェック
（is_deleted=FALSE / is_locked=FALSE）
- APIサーバー → APIサーバー: パスワード検証
（bcrypt照合）
- APIサーバー → データベース: ログイン成功時：failed_login_count=0リセット
last_login_at更新
- APIサーバー → データベース: セッション作成
（sessions INSERT / expires_at=現在+30分）
- APIサーバー → データベース: 監査ログ記録
（LOGIN_SUCCESS / IPアドレス・UserAgent）
  - APIサーバー ← フロントエンド: 200 OK
（HttpOnly Cookie: session_id）
※is_password_set=FALSEの場合はパスワード設定画面URLを返却
  - フロントエンド ← SE管理者: ダッシュボード画面へ遷移
（またはパスワード設定画面へリダイレクト）

## ユーザー認証

パスワード不一致時のカウント増加および5回失敗時のアカウントロック処理。

**参加者:** SE管理者 (actor)、フロントエンド (system)、APIサーバー (system)、データベース (database)

**メッセージフロー:**
- SE管理者 → フロントエンド: 誤ったパスワードを入力 → ログインボタン押下
- フロントエンド → APIサーバー: POST /api/auth/login
{email, password}
- APIサーバー → データベース: SE管理者情報取得
  - データベース ← APIサーバー: SE管理者レコード
- APIサーバー → APIサーバー: パスワード検証 → 不一致
- APIサーバー → データベース: failed_login_countインクリメント
（5回到達時：is_locked=TRUEに更新）
- APIサーバー → データベース: 監査ログ記録
（LOGIN_FAILURE または ACCOUNT_LOCK）
  - APIサーバー ← フロントエンド: 401 Unauthorized
（AUTH_001: 認証失敗 / AUTH_002: アカウントロック）
  - フロントエンド ← SE管理者: エラーメッセージ表示

```mermaid
{email, password}

    db-->>api: SE管理者レコード

    frontend-->>admin: エラーメッセージ表示
```

## SE管理者アカウント管理

SE管理者が別のSE管理者アカウントを論理削除する処理。自己削除・最終管理者削除は不可。

**参加者:** SE管理者（操作者） (actor)、フロントエンド (system)、APIサーバー (system)、データベース (database)

**メッセージフロー:**
- SE管理者（操作者） → フロントエンド: 削除対象アカウント選択 → 削除ボタン押下
- フロントエンド → APIサーバー: DELETE /api/se-admin-users/{seAdminUserId}
（Cookie: session_id）
- APIサーバー → APIサーバー: セッション検証（ミドルウェア）
- APIサーバー → データベース: 対象SE管理者情報取得
  - データベース ← APIサーバー: SE管理者レコード
（is_deleted, is_locked）
- APIサーバー → APIサーバー: 削除可否チェック
（自己削除禁止 / 最終管理者保護 ※要確認 / is_deleted=FALSE確認）
- APIサーバー → データベース: 論理削除更新
（is_deleted=TRUE, deleted_at=現在時刻, updated_at）
  - データベース ← APIサーバー: 更新完了
- APIサーバー → データベース: 対象アカウントのアクティブセッション全削除
（sessions DELETE）
- APIサーバー → データベース: 監査ログ記録
（SE_ADMIN_DELETE）
  - APIサーバー ← フロントエンド: 200 OK
（削除完了メッセージ）
  - フロントエンド ← SE管理者（操作者）: SE管理者一覧を更新して表示
