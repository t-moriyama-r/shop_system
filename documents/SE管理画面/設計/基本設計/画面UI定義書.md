# 画面UI定義書

> バージョン: 2 | 更新日時: 2026/7/12 0:00:00

## [SCR-001] ログイン画面

- **カテゴリ:** 認証
- **targetUser:** SE管理ユーザー
- **overview:** SE管理ユーザーがシステムにアクセスするための認証画面。メールアドレスとパスワードを入力してログインを実行する。認証失敗時はエラーメッセージをインライン表示し、再入力を促す。初期パスワード未変更（must_change_password=true）の場合は、ログイン成功後にパスワード変更画面へ強制遷移させる。
**コンポーネント:**

| name | type | 説明 |
| --- | --- | --- |
| ページヘッダー | header | システム名称・ロゴを表示するシンプルなヘッダー領域。ナビゲーションメニューは持たない。 |
| ログインフォーム | form | メールアドレス入力欄・パスワード入力欄・ログインボタンで構成される中央配置のカード型フォーム。 |
| エラーメッセージ表示エリア | card | 認証失敗時にフォーム上部へインライン表示されるアラート領域。エラー内容を簡潔なテキストで通知する。 |

**operationSteps:**

| step | action | systemResponse |
| --- | --- | --- |
| 1 | ユーザーがブラウザでログイン画面URL（/login）へアクセスする | ログインフォームを表示する。既にセッションが有効な場合はダッシュボード画面（/dashboard）へリダイレクトする。 |
| 2 | ユーザーがメールアドレス入力欄にメールアドレスを入力する | 入力値をフォームフィールドに反映する。 |
| 3 | ユーザーがパスワード入力欄にパスワードを入力する（マスク表示） | 入力値をマスク（●●●●）で表示する。 |
| 4 | ユーザーが「ログイン」ボタンをクリックする | 入力値のフロントエンドバリデーション（必須チェック・メールアドレス形式チェック）を実行する。バリデーションエラーがある場合は各入力欄の下にエラーメッセージを表示してステップ2へ戻る。バリデーション通過後、認証APIへリクエストを送信しローディング状態に遷移する。 |
| 5 | （システム処理）認証APIがDBの認証情報とbcryptで照合する | 認証成功かつ初期パスワード変更済み（must_change_password=false）の場合：セッションを開始しダッシュボード画面（/dashboard）へ遷移する。認証成功かつ初期パスワード未変更（must_change_password=true）の場合：セッションを開始し初期パスワード変更画面（/password/setup）へ強制遷移する。認証失敗の場合：エラーメッセージ（「メールアドレスまたはパスワードが正しくありません」）をフォーム上部に表示し、パスワード入力欄をクリアしてステップ2へ戻る。 |

**fields:**

| name | type | required | バリデーション | 説明 |
| --- | --- | --- | --- | --- |
| メールアドレス | email | true | 必須入力。メールアドレス形式（xxx@xxx.xxx）であること。最大254文字。 | SE管理ユーザーのログインIDとなるメールアドレスを入力する欄。 |
| パスワード | password | true | 必須入力。入力値はマスク表示する。※要確認（パスワードポリシー：最小文字数・使用可能文字種別等） | SE管理ユーザーのパスワードを入力する欄。入力値はマスク表示される。 |

**events:**

| トリガー | action | 説明 |
| --- | --- | --- |
| 「ログイン」ボタンクリック | フロントエンドバリデーション実行 → 認証APIコール → 結果に応じた画面遷移またはエラー表示 | 入力値の形式チェック後、サーバーサイドで認証を実行する。結果に応じてダッシュボード・初期パスワード変更画面への遷移またはエラー表示を行う。 |
| Enterキー押下（フォーム内） | 「ログイン」ボタンクリックと同等の処理を実行する | キーボード操作によるフォーム送信のサポート。 |
| メールアドレス入力欄のフォーカスアウト | メールアドレス形式のリアルタイムバリデーションを実行し、不正な場合は入力欄下にエラーメッセージを表示する | 入力欄からフォーカスが外れた際の即時フィードバック。 |

**transitions:**

| action | destination | condition |
| --- | --- | --- |
| ログイン成功（初期パスワード変更済み） | SCR-003 | 認証APIが成功レスポンスを返し、かつ初期パスワードから変更済み（must_change_password=false）である場合 |
| ログイン成功（初期パスワード未変更） | SCR-002 | 認証APIが成功レスポンスを返し、かつ初期パスワード未変更（must_change_password=true）である場合 |


## [SCR-002] 初期パスワード変更画面

- **カテゴリ:** 認証
- **targetUser:** SE管理ユーザー（初期パスワード未変更ユーザー）
- **overview:** CLIによって追加されたSE管理ユーザーが、初期パスワード未変更（must_change_password=true）の状態でログインした際に強制遷移される画面。画面見出しは「初期パスワードの変更」とし、メールで送付された初期パスワードから新しいパスワードへ変更する。新しいパスワードと確認用パスワードを入力して変更を完了させる。パスワード変更完了後はダッシュボード画面へ遷移する。本画面は初期パスワード未変更ユーザーのみがアクセス可能であり、変更完了後（must_change_password=false）にアクセスした場合はダッシュボードへリダイレクトする（APIは409を返す）。
**コンポーネント:**

| name | type | 説明 |
| --- | --- | --- |
| ページヘッダー | header | システム名称・ロゴを表示するシンプルなヘッダー領域。ナビゲーションメニューは持たない。 |
| パスワード変更フォーム | form | 新しいパスワード入力欄・確認用パスワード入力欄・変更完了ボタンで構成される中央配置のカード型フォーム。画面上部に案内メッセージ「メールで送付された初期パスワードから、新しいパスワードへ変更してください。」を表示する。 |
| パスワードポリシー案内 | card | 設定可能なパスワードの要件（文字数・使用可能文字種等）をフォーム近傍に表示するテキスト領域。※要確認（パスワードポリシーの詳細定義） |
| エラーメッセージ表示エリア | card | バリデーションエラー（パスワード不一致・ポリシー違反等）をフォーム上部または入力欄下にインライン表示するアラート領域。 |

**operationSteps:**

| step | action | systemResponse |
| --- | --- | --- |
| 1 | ユーザーがログイン画面で初期パスワード未変更（must_change_password=true）の状態でログインし、本画面へ強制遷移される | パスワード変更フォームと案内メッセージ・パスワードポリシーを表示する。 |
| 2 | ユーザーが「新しいパスワード」入力欄に新しいパスワードを入力する（マスク表示） | 入力値をマスク（●●●●）で表示する。パスワードポリシーの充足状況をリアルタイムで視覚フィードバックする。※要確認（強度インジケーターの有無） |
| 3 | ユーザーが「パスワード確認」入力欄に同じパスワードを再入力する（マスク表示） | 入力値をマスク（●●●●）で表示する。 |
| 4 | ユーザーが「パスワードを変更する」ボタンをクリックする | フロントエンドバリデーション（必須チェック・ポリシー準拠チェック・2フィールド一致チェック）を実行する。エラーがある場合は各入力欄下またはフォーム上部にエラーメッセージを表示してステップ2へ戻る。バリデーション通過後、パスワード変更APIへリクエストを送信しローディング状態に遷移する。 |
| 5 | （システム処理）パスワード変更APIがDBのパスワードを更新し、must_change_passwordをfalseへ更新する | 変更成功の場合：セッションを継続しダッシュボード画面（/dashboard）へ遷移する。変更失敗の場合：エラーメッセージをフォーム上部に表示してステップ2へ戻る。 |

**fields:**

| name | type | required | バリデーション | 説明 |
| --- | --- | --- | --- | --- |
| 新しいパスワード | password | true | 必須入力。パスワードポリシーを満たすこと。入力値はマスク表示する。※要確認（最小文字数・大文字小文字数字記号の要件等パスワードポリシーの詳細） | 新たに設定するパスワードを入力する欄。入力値はマスク表示される。 |
| パスワード確認 | password | true | 必須入力。「新しいパスワード」入力欄と完全一致すること。入力値はマスク表示する。 | 入力ミスを防ぐため、新しいパスワードを再度入力する確認用欄。 |

**events:**

| トリガー | action | 説明 |
| --- | --- | --- |
| 「パスワードを変更する」ボタンクリック | フロントエンドバリデーション実行 → パスワード変更APIコール → 結果に応じたダッシュボードへの遷移またはエラー表示 | 必須チェック・ポリシー準拠チェック・2フィールド一致チェックを実施後、DBのパスワードを更新する。 |
| 「パスワード確認」入力欄のフォーカスアウト | 「新しいパスワード」との一致チェックを実行し、不一致の場合は入力欄下にエラーメッセージ（「パスワードが一致しません」）を即時表示する | 確認用フィールドのフォーカスアウト時の即時バリデーションフィードバック。 |
| 「新しいパスワード」入力欄への入力（リアルタイム） | 入力中にパスワードポリシーの各要件充足状況を視覚的にフィードバックする（チェックアイコン等） | ユーザーがパスワード要件を満たしているか確認できるリアルタイムフィードバック。※要確認（実装有無・表示仕様） |

**transitions:**

| action | destination | condition |
| --- | --- | --- |
| パスワード変更完了 | SCR-003 | パスワード変更APIが成功レスポンスを返した場合 |
| ブラウザバック・直接URL入力によるアクセス（変更完了済みユーザー） | SCR-003 | 初期パスワード変更済み（must_change_password=false）のユーザーが本画面へアクセスしようとした場合、ダッシュボードへリダイレクトする（APIは409を返す）。 |


## [SCR-003] ダッシュボード画面

- **カテゴリ:** メイン
- **targetUser:** SE管理ユーザー
- **overview:** ログイン成功後に最初に表示されるトップ画面。システム全体のサマリー情報と顧客アカウント発行状況の一覧を表示する。具体的なコンテンツや表示データの詳細は二次開発にて実装予定であり、一次開発ではレイアウト・プレースホルダーおよびナビゲーション構造の実装を行う。
**コンポーネント:**

| name | type | 説明 |
| --- | --- | --- |
| グローバルヘッダー | header | システム名称・ロゴ、ログインユーザーのメールアドレス表示、ログアウトボタンを含む全画面共通ヘッダー。 |
| サイドバーナビゲーション | sidebar | ダッシュボード・顧客アカウント管理・SE管理者アカウント管理など主要機能へのナビゲーションリンクを縦並びで配置するサイドバー。現在表示中のメニューをハイライト表示する。 |
| システム稼働サマリーエリア | card | システムの稼働状況やKPIサマリーをカード形式で表示するエリア。二次開発にて具体的な表示内容を実装予定。一次開発ではプレースホルダー表示。※要確認（表示対象メトリクスの詳細定義） |
| 顧客アカウント発行状況一覧 | table | 直近で実行された顧客アカウント発行処理の一覧テーブル。会社名・メールアドレス・発行日時・ステータス（成功・処理中・エラー）等を表示する。二次開発にて詳細実装予定。※要確認（表示件数・ソート・検索条件の詳細） |
| 顧客アカウント新規発行ボタン | button-group | 顧客アカウント新規発行画面（/customers/new）へ遷移するための主要アクションボタン。ダッシュボード上部または発行状況一覧の近傍に配置する。 |

**operationSteps:**

| step | action | systemResponse |
| --- | --- | --- |
| 1 | ユーザーがログイン画面またはパスワード設定画面を経てダッシュボードへ遷移する、またはサイドバーの「ダッシュボード」リンクをクリックする | システム稼働サマリー情報と顧客アカウント発行状況一覧をAPIから取得して表示する。データ取得中はローディングインジケーターを表示する。 |
| 2 | ユーザーが画面上のサマリー情報や発行状況一覧を閲覧する | 取得済みデータを表示し続ける。 |
| 3 | ユーザーが「顧客アカウント新規発行」ボタンをクリックする | 顧客アカウント新規発行画面（/customers/new）へ遷移する。 |
| 4 | ユーザーがグローバルヘッダーの「ログアウト」ボタンをクリックする | セッションを破棄し、ログイン画面（/login）へ遷移する。 |

**fields:**


**events:**

| トリガー | action | 説明 |
| --- | --- | --- |
| 画面初回表示・ページリロード | システム稼働サマリー情報取得APIおよび顧客アカウント発行状況一覧取得APIを呼び出し、取得結果を各エリアへ描画する | 画面表示時のデータフェッチ処理。取得失敗時はエラーメッセージをエリア内に表示する。※要確認（自動更新インターバルの有無） |
| 「顧客アカウント新規発行」ボタンクリック | 顧客アカウント新規発行画面（/customers/new）へ画面遷移する | 新規顧客アカウント発行フローへのエントリーポイント。 |
| 「ログアウト」ボタンクリック（グローバルヘッダー） | セッション破棄APIを呼び出し、ログイン画面（/login）へ遷移する | 全画面共通のログアウト処理。 |
| サイドバーナビゲーションリンククリック | クリックされたリンクに対応する画面へ遷移する | グローバルナビゲーションによる画面間遷移。 |

**transitions:**

| action | destination | condition |
| --- | --- | --- |
| 「顧客アカウント新規発行」ボタンクリック | SCR-004 | 常時遷移可能 |
| 「ログアウト」ボタンクリック | SCR-001 | セッション破棄完了後 |
| 未認証状態でのアクセス | SCR-001 | セッションが無効または期限切れの場合、ログイン画面へリダイレクトする |


## [SCR-004] 顧客アカウント新規発行画面

- **カテゴリ:** 顧客管理
- **targetUser:** SE管理ユーザー
- **overview:** 新規顧客アカウントを発行するための情報入力フォーム画面。会社名・担当者名・メールアドレス等の必要情報を入力し、登録処理を実行する。入力値のバリデーションエラーはインライン表示する。登録完了後は顧客アカウント発行完了画面へ遷移し、顧客へ通知メールが送信される。
**コンポーネント:**

| name | type | 説明 |
| --- | --- | --- |
| グローバルヘッダー | header | システム名称・ロゴ、ログインユーザーのメールアドレス表示、ログアウトボタンを含む全画面共通ヘッダー。 |
| サイドバーナビゲーション | sidebar | 全画面共通のサイドバーナビゲーション。「顧客アカウント管理」メニューをハイライト表示する。 |
| ページタイトル・パンくずリスト | header | 「顧客アカウント新規発行」のページタイトルとダッシュボードへのパンくずリストを表示するエリア。 |
| 顧客情報入力フォーム | form | 会社名・担当者名・メールアドレス等の顧客情報入力欄と、「発行する」ボタン・「キャンセル」ボタンで構成されるメインフォーム。各入力欄にはラベル・プレースホルダー・バリデーションエラーメッセージ表示領域を持つ。 |
| フォームアクションボタングループ | button-group | 「発行する」（プライマリボタン）と「キャンセル」（セカンダリボタン）を横並びに配置したボタングループ。フォーム末尾に配置する。 |
| インラインエラーメッセージ | card | 各入力欄のバリデーションエラーを該当欄直下にインライン表示するエラー表示領域。フォーム上部には全体エラーサマリーも表示する。 |

**operationSteps:**

| step | action | systemResponse |
| --- | --- | --- |
| 1 | ユーザーがダッシュボードの「顧客アカウント新規発行」ボタンをクリックして本画面へ遷移する | 顧客情報入力フォームを初期状態（空欄）で表示する。 |
| 2 | ユーザーが各入力欄に顧客情報を入力する | 入力値をフォームフィールドに反映する。フォーカスアウト時にリアルタイムバリデーションを実行し、エラーがある場合は入力欄下にインラインエラーを表示する。 |
| 3 | ユーザーが「発行する」ボタンをクリックする | 全入力欄のフロントエンドバリデーション（必須チェック・形式チェック）を実行する。エラーがある場合は該当欄にインラインエラーを表示してステップ2へ戻る。バリデーション通過後、顧客アカウント登録APIへリクエストを送信しローディング状態に遷移する。 |
| 4 | （システム処理）顧客アカウント登録APIがバリデーション・重複チェック・DB登録を実行する | 登録成功の場合：顧客アカウント発行完了画面（/customers/complete）へ遷移する。重複エラー（メールアドレス重複等）の場合：フォーム上部にエラーメッセージを表示してステップ2へ戻る。その他エラーの場合：フォーム上部にシステムエラーメッセージを表示する。 |
| 5 | ユーザーが「キャンセル」ボタンをクリックする | 入力内容を破棄し、ダッシュボード画面（/dashboard）へ遷移する。※要確認（入力途中のキャンセル時に確認ダイアログを表示するか否か） |

**fields:**

| name | type | required | バリデーション | 説明 |
| --- | --- | --- | --- | --- |
| 会社名 | text | true | 必須入力。最大100文字。※要確認（文字種制限の有無） | 顧客の会社名・組織名を入力する欄。 |
| 担当者名 | text | true | 必須入力。最大50文字。※要確認（姓・名を別フィールドに分けるか否か） | 顧客の担当者氏名を入力する欄。 |
| メールアドレス | email | true | 必須入力。メールアドレス形式（xxx@xxx.xxx）であること。最大254文字。既存アカウントとの重複不可（サーバーサイドチェック）。 | 顧客のログインIDおよび通知送信先となるメールアドレスを入力する欄。 |
| 電話番号 | text | false | 任意入力。数字・ハイフンのみ使用可。最大20文字。※要確認（必須/任意の区別、形式要件） | 顧客の連絡先電話番号を入力する欄。※要確認（項目の有無・必須/任意の区別） |
| 備考 | textarea | false | 任意入力。最大500文字。※要確認（項目の有無） | 顧客に関する補足情報を自由記述する欄。※要確認（項目の有無） |

**events:**

| トリガー | action | 説明 |
| --- | --- | --- |

## [SCR-008] エラー画面（共通）

- **カテゴリ:** 共通基盤
- **targetUser:** SE管理ユーザー（システム管理者）
- **overview:** システム内で予期しない例外エラー（サーバーエラー、ネットワークエラー、存在しないページへのアクセス等）が発生した場合に表示される共通エラー画面。エラーコードとユーザー向けメッセージを表示し、ダッシュボードまたはログイン画面への復帰導線を提供する。すべての画面からの共通遷移先として機能する。
**コンポーネント:**

| name | type | 説明 |
| --- | --- | --- |
| グローバルヘッダー | header | システム名ロゴを含むヘッダー。ログイン状態の場合はナビゲーションメニューとログアウトボタンも表示する。ログイン状態が不明またはセッション切れの場合はロゴのみ表示する。 |
| エラーコンテンツエリア | card | エラーアイコン（警告・エラーを示すアイコン）、エラーコード（例：500、404等）、エラータイトル（例：「サーバーエラーが発生しました」）、ユーザー向けエラーメッセージを縦方向に配置したメインコンテンツカード。画面中央に配置する。※要確認（エラーコード体系・表示メッセージの詳細定義） |
| 復帰ナビゲーションボタングループ | button-group | 「ダッシュボードへ戻る」ボタンと「ログイン画面へ」ボタンを提供するボタングループ。ログイン済みの場合は「ダッシュボードへ戻る」をプライマリボタンとして表示する。セッション切れまたは未ログインの場合は「ログイン画面へ」ボタンのみ表示する。※要確認（ログイン状態の判定方法と表示ボタンの切り替えロジック） |
| エラー参照ID表示エリア | card | エラー発生時のトレーサビリティのため、エラー参照ID（エラーログとの紐付けに使用するユニークID）を小テキストで表示するエリア。SE管理者が問い合わせやログ調査の際に利用する。※要確認（エラー参照IDの採番方式・表示の要否） |

**operationSteps:**

| step | action | systemResponse |

| 2 | SE管理者がエラーコード・メッセージ・エラー参照IDを確認する | エラーコンテンツエリアの表示を維持する。自動的なページリロードや追加処理は行わない。 |
| 3 | 「ダッシュボードへ戻る」ボタンをクリックする（ログイン済みの場合） | SCR-003（ダッシュボード画面）へ遷移する。 |
