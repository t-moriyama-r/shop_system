# システム概要

> バージョン: 5 | 更新日時: 2026/7/12 0:00:00

### システム構成概要

- **content:** 本システムは「SE管理画面」として、一般ユーザー向けのマイページ・ログイン機能とは完全に分離された、システム管理者（SE担当者）専用の独立したWebアプリケーションである。

主要コンポーネントは以下の通り：

【Webアプリケーション層】
・ログイン画面：メールアドレス／パスワードによる管理者認証エントリポイント
・ダッシュボード画面：システムサマリー・顧客アカウント発行状況の一覧表示
・顧客アカウント新規発行画面：顧客情報の入力・登録・完了通知送信
・パスワード設定画面：SE管理者アカウントの初期パスワードの変更
・SE管理者アカウント削除画面：SE管理者アカウントの削除操作

【SE管理者アカウント登録方式】
・SE管理者アカウントの新規追加はCLIツールにより実施する。CLIがランダム初期パスワードを自動生成し、bcryptによるハッシュ化でDBへ登録するとともに、初期パスワードをAWS SES経由で本人宛にメール送信する
・Web画面からは新規アカウント登録は行えず、初回ログイン後にパスワード設定画面にて初期パスワードから新しいパスワードへの変更を強制する運用とする

【データベース層】
・全システム共通のPostgreSQLデータベースを使用
・SE管理者アカウント情報（メールアドレス、パスワードハッシュ、ロック状態等）の永続化
・顧客アカウント情報の永続化
・操作ログ・監査ログの保存（保持期間：1年間）

【外部連携】
・顧客向け管理画面システム（別システム）との顧客アカウントデータは全システム共通DBを介して連携
・AWS SESによる顧客アカウント発行完了通知メールおよびSE管理者アカウント発行時の初期パスワード通知メール送信
・Sentryによるエラー監視・アラート通知

### 使用技術スタック

- **content:** 【フロントエンド】
・フレームワーク：React
・UIライブラリ：Tailwind CSS / MUI（Material UI）/ Headless UI
・配信方式：AWS S3 + CloudFront経由で配信
・通信プロトコル：HTTPS（TLS 1.2以上）

【バックエンド】
・言語／フレームワーク：TypeScript / Hono
・認証方式：セッションベース認証（セッションタイムアウト：30分）
・APIアーキテクチャ：REST API

【データベース】
・RDBMS：PostgreSQL（全システム共通DB）
・パスワード保存方式：ソルト付きハッシュ化（bcrypt）

【インフラ・ミドルウェア】
・クラウドプラットフォーム：AWS
・WebサーバーまたはリバースProxy：Nginx（SSL終端・静的ファイル配信）
・バックエンド実行環境：AWSマネージドサービス（ECS / EC2等）

【メール送信】
・メール送信サービス：AWS SES

【バックアップ】
・バックアップ先：AWS S3

【監視・ログ管理】
・エラー監視ツール：Sentry
・ログ収集・保管：未定義 ※要確認

### システム間連携

- **content:** 本SE管理画面は独立したシステムとして構築されるが、以下の外部システム・サービスとの連携が発生する。

【1. 顧客向け管理画面システム（別システム）】
・連携種別：データ連携（顧客アカウント情報）
・方向：SE管理画面 → 全システム共通DB → 顧客向け管理画面システム
・内容：SE管理画面で発行した顧客アカウント情報は全システム共通のPostgreSQLデータベースへ登録されることで、顧客向け管理画面システムからも参照・利用が可能となる
・連携方式：全システム共通DBスキーマを介した共有データアクセス

【2. AWS SES（メール送信サービス）】
・連携種別：外部サービス連携
・方向：SE管理画面バックエンド（Hono） → AWS SES
・内容：顧客アカウント発行完了時の初期ID・一時パスワード・利用案内メール、およびSE管理者アカウント発行時の初期パスワード通知メールの自動送信
・連携方式：AWS SES API（AWS SDK for JavaScript/TypeScript を利用）

【3. Sentry（エラー監視・アラート通知）】
・連携種別：監視連携
・方向：SE管理画面（フロントエンド／バックエンド） → Sentry → 運用管理者
・内容：アプリケーションの例外・エラー検知時に運用管理者へ即時アラート通知。フロントエンド（React）およびバックエンド（Hono）双方にSentry SDKを組み込む
・連携方式：Sentry SDK（JavaScript / Node.js）

【4. バックアップ基盤（AWS S3）】
・連携種別：データバックアップ
・内容：管理者・顧客アカウントデータおよび操作ログの日次自動バックアップ（30日世代管理）
・連携方式：AWS S3へのバックアップデータ格納

### データフロー概要

- **content:** 【フロー1: SE管理者ログイン】
①管理者がブラウザよりログイン画面にアクセス（HTTPS）
②メールアドレス・パスワードを入力しサブミット
③HonoバックエンドがPostgreSQLよりアカウント情報を取得し、bcryptによるハッシュ照合で認証検証
④認証成功：セッション発行 → ダッシュボード画面へリダイレクト
⑤認証失敗：エラーメッセージを返却。連続失敗5回でアカウントロック状態をPostgreSQLへ記録
⑥ログイン成否いずれも操作ログをPostgreSQLへ記録

【フロー2: SE管理者アカウント追加】
①CLIツールがランダム初期パスワードを自動生成し、bcryptによりソルト付きハッシュ化してPostgreSQLへアカウント情報を登録
②初期パスワードの平文をAWS SES経由で対象の管理者本人宛にメール送信（送信失敗時はアカウント作成ごとロールバックし、操作ログにFAILUREを記録）
③対象の管理者が初回ログイン後、パスワード設定画面にて初期パスワードから新しいパスワードへの変更を強制される（変更後のパスワードもbcryptによりソルト付きハッシュ化してPostgreSQLへ保存）

【フロー3: 顧客アカウント新規発行】
①管理者がReact製の顧客アカウント発行画面にて必要情報（会社名、担当者名、メールアドレス等）を入力
②Honoバックエンドにてバリデーション（形式チェック・必須チェック・重複チェック）を実行
③バリデーション通過後、顧客アカウント情報を全システム共通PostgreSQLへ新規登録（Create）
④登録完了をトリガーとし、AWS SES経由で顧客宛てに初期ID・一時パスワード・利用案内メールを送信
⑤顧客アカウント発行処理の結果（成功・失敗）を操作ログとしてPostgreSQLへ記録
⑥ダッシュボードの顧客アカウント発行状況一覧に結果が反映され、管理者が確認可能となる

【フロー4: ダッシュボード情報取得】
①管理者がダッシュボード画面にアクセス
②HonoバックエンドのREST APIがPostgreSQLよりシステムサマリー情報・顧客アカウント発行状況を取得
③取得データをReactフロントエンドへ返却し画面に描画

【フロー5: エラー監視（Sentry）】
①フロントエンド（React）またはバックエンド（Hono）で例外・エラーが発生
②Sentry SDKが自動キャプチャし、Sentryプラットフォームへ送信
③Sentryが運用管理者へアラート通知

【フロー6: バックアップ】
①日次バッチ処理によりPostgreSQL内の管理者アカウント・顧客アカウント・操作ログデータを自動バックアップ
②バックアップデータをAWS S3へ格納し、30世代分を保持

### セキュリティ概要

- **content:** SE管理画面は一般ユーザー向けシステムとは完全に分離された管理者専用システムであるため、以下のセキュリティ対策を実施する。

【アクセス制御・認証】
・ログイン手段：メールアドレス／パスワードによる認証のみ
・SE管理者アカウント追加はCLIツールによる登録のみ実施（Web画面からの新規登録は不可）
・アカウントロック機能：同一アカウントへの連続ログイン失敗5回でロック。解除はDB直接操作にて実行

【セッション管理】
・ログイン成功後にセッションを発行し、無操作状態30分経過でセッション自動破棄・ログイン画面へ強制遷移
・ログアウト操作によるセッションの明示的な破棄

【通信の暗号化】
・管理画面へのすべてのWebアクセスはHTTPS（TLS 1.2以上）を必須とし、NginxにてSSL終端を実施
・PostgreSQL等の内部通信はすべて暗号化通信を適用すること ※要確認

【パスワード管理】
・パスワードポリシー：半角英数字・記号混在、8文字以上
・DBへの保存はbcryptによるソルト付きハッシュ化を採用
・SE管理者アカウントの初期登録時はCLIがランダム初期パスワードを自動生成し、AWS SES経由で本人宛にメール送信。初回ログイン後にパスワード設定画面で初期パスワードからの変更を強制

【エラー監視・インシデント対応】
・Sentryをフロントエンド（React）およびバックエンド（Hono）に組み込み、例外・エラーを自動検知し運用管理者へ通知

【監査・操作ログ】
・記録対象：管理者ログイン成否、顧客アカウント発行操作の実行履歴（実行日時・実行者・操作種別・対象情報）
・ログ保持期間：1年間
・ログデータは改ざん・不正削除を防止する保存方式を採用すること ※要確認

【その他セキュリティ考慮事項】
・CSRF対策、XSS対策、SQLインジェクション対策等の一般的なWebアプリケーションセキュリティ対策を実施 ※要確認（具体的な対策ポリシーはドメイン知識・技術制約が未提供のため要確認）

### インフラ構成概要

- **content:** ※インフラストラクチャ設計・構築はアウトスコープであり、一部推測補完を含みます。確定前に要確認。

【クラウドプラットフォーム】
・AWS を採用
・将来的なスケールアップ・アウトに対応可能なクラウドネイティブ構成を推奨

【Webアプリケーション層】
・リバースProxy：Nginx（SSL終端・静的ファイル配信を担当）
・フロントエンド：ReactビルドアセットをAWS S3 + CloudFront経由で配信
・バックエンド：Hono（TypeScript）をAWSマネージドサービス（ECS / EC2等）上で稼働
・ロードバランサー：同時アクセス10名程度の小規模構成のため当初は単一構成も許容、拡張性を考慮した上で設計 ※要確認

【データベース層】
・DB種別：PostgreSQL（全システム共通DB）
・構成：Amazon RDS for PostgreSQL を推奨 ※要確認
・バックアップ：日次自動バックアップ、AWS S3へ格納し30世代保持

【メール送信】
・AWS SES を利用した通知メール送信基盤（顧客向け・SE管理者向け）を構築

【ネットワーク】
・管理画面へのアクセスはHTTPS（TLS 1.2以上）を必須（NginxにてSSL終端）
・PostgreSQLはパブリックネットワークからの直接アクセスを遮断し、アプリケーション層経由のプライベートネットワーク接続のみ許可

【監視・ログ管理】
・エラー監視：Sentryをフロントエンド（React）およびバックエンド（Hono）に組み込み、例外・エラー発生時に運用管理者へ即時アラート通知
・ログ収集・保管：未定義 ※要確認

【可用性目標（※要確認）】
・稼働率：平日9:00〜18:00において99.5%以上
・RTO / RPO：未定義（ディザスタリカバリポリシーが未提供のため ※要確認）
